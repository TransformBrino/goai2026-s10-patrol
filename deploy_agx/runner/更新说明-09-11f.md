# runner 更新说明 · 2026-09-11f（在 0911e 基础上只改一处；作者 09-11 拍板）

**一句话**：收到 `/climb_mode 2`（楼梯专家）而 runner 没加载楼梯策略（`S10_POLICY_PIT`）时，**留在主策略**，不再落到上墙专家 ClimbH，并打印一条醒目警告。其余行为和 0911e 完全一样。

## 改动（只有一个文件）
`s10_ws/src/S10_sdk_deploy/state_machine/quadruped_wheel/rl_control_state.hpp`
- 去 CR md5：`070924802e42de61d59c5183277ee744`（0911e 版是 `136b94137a781848159f13b549284523`）。
- 补丁见 `runner_0911e_to_0911f.patch`。

**原来的选择逻辑**
- 如果 sel > 1.5 且楼梯槽已加载，就切到楼梯专家；
- 否则，如果 sel > 0.5 且上墙槽已加载，就切到上墙专家。

所以没加载楼梯槽时按 2，会落进第二个分支，切到 ClimbH。

**现在**
- sel > 1.5 时只看楼梯槽。没加载就留在主策略，并打印：
  `!! [CLIMB] 收到楼梯专家请求（/climb_mode 2），但楼梯策略 S10_POLICY_PIT 没加载，留在主策略（0911f）`
- 这条警告每按一次 2 只打一次。回到 0 或 1 之后再按 2，会再打；重新进入 RL 状态时，也会再打一次。
- 顺带去掉了外层"至少加载了一个专家槽才做判断"的条件。这样两个专家槽都没加载时按 2，也会打这条警告。除此之外，行为不变。

**注意**
- `ros_command_interface.hpp` 没改，md5 仍是 `fd078c9e…`。它收到 2 时照旧会打印 `[CLIMB] 切到坑内策略`，这一行只表示"收到了指令"。
- 实际切没切，要看 rl_control_state 打印的内容：
  - `[policy] 切换到 坑内策略`：切了；
  - 上面那条 `!!` 警告：没切。
- 代码里第三个槽沿用旧名"坑内"，它就是楼梯专家。

## AGX 上怎么装
1. 先备份 AGX 上原来的 `rl_control_state.hpp`。
2. 把本包里的 `rl_control_state.hpp` 覆盖到 AGX 源码树的同一位置。
3. 照原来的方式，用 colcon 编译 `s10_sdk_deploy`。
4. 编译完用 `strings rl_deploy | grep -c 0911f` 确认，结果应该至少是 1。

启动时三个槽可以同时加载：
- `S10_POLICY_PATH`：主策略；
- `S10_POLICY_CLIMB`：ClimbH；
- `S10_POLICY_PIT`：楼梯专家。

这三份策略都属于标准 0.42 站姿组：`S10_DEF_HIPX=0.05`、`S10_DEF_HIPY=0.35`、`S10_DEF_KNEE=0.65`、`S10_KD_WHEEL=0.8`。
